# OA-5 and OA-6 owner sitting runbook (RC-4 baseline; RC-7 single sitting at the end)

Draft for Eric's review. The agent does not submit.

Last verified commit: `ea0d579547febf03c6dd6f9bcaafcf5e2f49fc70` (`main` after FP-26 PR-B #216; re-read for release candidate RC-7). The full sitting below was written for RC-4 and stays the baseline; the RC-5 arena re-check, the RC-6 re-check and the RC-7 single sitting (the same steps retargeted, plus R7, R8, a brand check and the registry install) are the last sections. Follow the RC-7 single sitting. The artifact the full sitting runs on is built from RC-4. Its commit, file name and sha256 are in `docs/release/evidence-checklist.md` section 6 and in the build record the agent hands you (step 0).

This is one consolidated sitting of at most 30 minutes, with two parts. Part 1 is OA-5 (issue #140): the update of your installed app to RC-4 and the integrated journey. It replaces the separate owner checks OA-2 (issue #101), OA-4 (issue #124) and the re-checks of FP-17, FP-19, FP-20 and FP-21, and it is the first live check of FP-22 and FP-23 (the PA-3 changes). It is the evidence for FP-14-AC01 and AC06 and closes BLK-01 in `docs/release/blockers.md`. Part 2 is OA-6 (issue #133): uninstall, clean install from the tarball, Trust modal wording, permissions view and re-enable behaviour. It is the evidence for FP-15-AC01 and confirms the "to be confirmed in OA-6" facts in `docs/release/install.md`. Part 2 ends by putting your own data back. One optional step (19) imports an avatar pack; it is not part of the 30 minutes.

What changed since RC-3, so you know what you are looking for: XP is credited automatically when a task the app observed ends cleanly, and nobody accepts anything. There is no Work tab. A bot starts with no Specter and you assign one (a walkthrough opens on first visit). The tab order is Arena, Roster, Specters, Data, and the Arena is first. The Specters tab is a showcase of the 11 heroes, and a bot's own avatar and XP are under Roster, then the bot, then Specter. Heroes get random places on the map. Minions are tasks, drawn small, medium or large by run time.

Who does what: steps 1 to 19 are yours, in your own terminal and browser. Crew refuses install, update and uninstall from an agent shell (`docs/compatibility/crew-0.12.2.md`, "Install method"). The agent runs step 0, writes down what you report and does not run your steps.

Starting state. Your installed app is most likely RC-3 (`610939061c23`, version `0.1.0`, store version `PRAGMA user_version` 9). RC-1 (`de533eb`, store version 6) or RC-2 (`9d4581c9`, store version 7) also update in one move, and the same steps hold. Where a check below says "gone" and it is already gone, record that. Write down which build you started from in step 2.

Crew version. The host is recorded as Kiro Crew 0.13.1 (2026-11-22). This repository has no compatibility note for 0.13.1 yet, so read `kirocrew --version` and record it in step 2. The install facts in `docs/release/install.md` were first read from the 0.12.2 source. The icon, "Waiting on you" and "Context in use" behaviour is read from the 0.13.0 source (`docs/compatibility/crew-0.13.0.md`). Nothing in those documents counts as live-tested until this sitting records it.

## Before you sit down (not counted in the 30 minutes)

- Have the RC-4 build record from step 0 and the artifact folder open.
- Create three new bots in Crew now (for example `sa-test-1`, `sa-test-2`, `sa-test-3`). Do not send them a message and do not open their chat until step 7: the app only sees a bot once it has been seen in a conversation, and a bot the old build sees first gets a hero by itself. If a new bot already shows in RC-3's roster with a hero, leave it alone and create three fresh bots after step 3.
- Set up one bot to show "Waiting on you". Use a bot whose tool use needs your approval in Crew (not one set to run tools without asking). Plan a turn that needs a tool, for example "list the files in the current folder". You will send it in step 6 and leave Crew's approval card unanswered. Which Crew setting makes a bot ask is not recorded in this repo; if no bot asks, record that and skip the waiting checks in steps 6, 9 and 11.
- Have one bot that answers a plain turn without a tool, for the Working check.
- Have one bot that can start a worker session. For step 10 you will ask it for a worker that takes about 4 minutes, for example: "Start a worker session to read through the files in this folder one by one and summarise each. Take about 4 minutes, and tell me when it is done."

## Time

Part 1 (steps 1 to 13) 22 minutes and Part 2 (steps 14 to 18) 8 minutes, which is the whole 30 with no slack. These are estimates, not timings. If the sitting runs over, stop after step 13 and run Part 2 later on the same artifact; record that. The reduced-motion check in step 11 is the first thing to drop if time is short, and is recorded as skipped. The result file records the actual time.

## Rollback (read before step 2)

Disable the app. Replace `~/.kiro/crew/apps/specter-arena/data` with `~/specter-data-backup-OA5` (the copy made in step 2). Enable the app. If the app is no longer installed, install the RC-4 folder first, then do the same, and expect the app to migrate the copied store again. An older build refuses a store at version 11, so do not install RC-1, RC-2 or RC-3 over a migrated store. If Part 2 fails after step 14, use `~/specter-data-after-OA5` instead, so the work from Part 1 is kept.

### Part C: registry install

This part installs Specters of the Abyss from the Kiro Crew external registry. Crew 0.13.1 is the tested version. Nothing in this part has been run on a real Crew until you run it. Fill the results table as you go and record failures verbatim. Do not mark steps done that were not run.

The registry is the repository `https://github.com/burlabs/specter-arena` on branch `main`. Crew builds the UI on your machine from that source, so **Node 22 or newer and `npm` must be on the PATH of the process that runs the Crew gateway**. A Node on your shell's PATH is not enough if the desktop app or the gateway starts with a different PATH. Install steps and the PATH fix are in `docs/release/install.md` section 2A.
